# 欠薪支持起诉智能办案平台（检察端）概要设计书（完善版）

## 1. 文档说明

### 1.1 编写目的

本文档在现有需求描述基础上，对“欠薪支持起诉智能办案平台（检察端）”进行概要设计层面的完善，重点完成以下内容：

* 对业务功能进行系统化分解，形成清晰的模块边界；
* 完善各功能模块的实现细节、交互逻辑与处理规则；
* 明确系统总体技术架构、部署架构、数据架构与安全架构；
* 为后续详细设计、数据库设计、接口设计、开发实施与验收提供依据。

### 1.2 适用范围

本文档适用于：

* 项目立项与方案评审；
* 产品、研发、测试、实施、运维团队协同；
* 检察业务部门对系统建设方案的审查确认；
* 后续详细设计说明书、接口说明书、数据库设计说明书的编制。

### 1.3 设计原则

1. **业务主导**：围绕支持起诉办案主流程设计系统能力。
2. **人机协同**：AI 仅作辅助研判与生成建议，最终决定权归检察官。
3. **全程留痕**：所有关键操作节点均可追溯、可审计、可归档。
4. **安全隔离**：严格满足“互联网前端 + 检察内网后端”物理隔离要求。
5. **可扩展性**：支持后续扩展更多案由、更多协同部门、更多智能能力。
6. **标准规范**：符合政务系统风格、检察业务系统规范、个人信息保护与数据安全要求。

## 2. 项目概述

### 2.1 建设背景

针对农民工欠薪线索收集分散、同案线索识别困难、支持起诉审查工作量大、文书制作重复、类案办理效率低、数据统计支撑不足等问题，建设“欠薪支持起诉智能办案平台（检察端）”，实现从线索接收、研判、审查、受理、调查取证、文书生成、审核审批、归档统计的全流程数字化办案。

### 2.2 建设目标

构建一个集“线索治理、AI 辅助审查、文书智能生成、批量类案办理、统计分析、安全审计”于一体的智能办案平台，实现：

* 线索统一归集与全生命周期闭环管理；
* 同工地/同企业/同包工头线索的智能聚合；
* 支持起诉受理条件的智能辅助审查；
* 法律文书智能生成与分级审核；
* 类案批量办理与类案规则辅助；
* 办案过程可追溯、文书可归档、数据可统计、风险可预警。

### 2.3 用户角色

| 角色         | 职责                      |
| ---------- | ----------------------- |
| 承办检察官      | 线索研判、审查、调查、文书制作、办结      |
| 部门负责人      | 文书审核、案件把关、督办            |
| 分管副检察长/检察长 | 重大案件审批                  |
| 系统管理员      | 用户权限、配置管理、日志审计、模板维护     |
| 外部协同单位接收方  | 接收移送/协查信息（人社、住建、属地检察院等） |

## 3. 总体设计

## 3.1 总体业务架构

系统围绕支持起诉办案主线，形成“1 个基础平台 + 7 大业务模块 + 3 类支撑能力”的总体业务架构。

### 3.1.1 七大业务模块

1. 系统首页与办案总览模块
2. 线索全生命周期管理模块
3. AI 辅助审查与办案模块
4. 法律文书智能生成与管理模块
5. 批量办案与类案管理模块
6. 数据统计与分析模块
7. 系统设置与安全保障模块

### 3.1.2 三类支撑能力

1. AI 智能引擎能力：OCR、ASR、NLP 语义识别、文书生成、规则推理
2. 业务中台能力：流程引擎、消息通知、权限控制、日志审计、模板中心
3. 数据支撑能力：主数据管理、案件数据仓库、检索索引、统计分析模型

## 3.2 总体技术架构

推荐采用“前后端分离 + 微服务/模块化服务 + AI 能力中台 + 数据中台”的技术架构。

### 3.2.1 架构分层

1. **展现层**

   * 检察内网 PC 端 Web 应用
   * 政务风格布局：左侧固定导航 + 右侧主工作区
2. **业务应用层**

   * 首页总览服务
   * 线索管理服务
   * 办案审查服务
   * 文书管理服务
   * 批量办案服务
   * 统计分析服务
   * 系统管理服务
3. **业务支撑层**

   * 工作流引擎
   * 规则引擎
   * 消息通知中心
   * 文件管理中心
   * 检索与索引服务
   * 审计日志服务
4. **智能能力层**

   * OCR 识别服务
   * 音视频转写服务
   * 语义匹配与聚合服务
   * AI 审查推理服务
   * 文书生成与润色服务
5. **数据层**

   * 业务数据库
   * 文件对象存储
   * 检索引擎
   * 数据仓库/统计库
   * 缓存服务
6. **基础设施层**

   * 检察内网服务器集群
   * 国密加密组件
   * 单向光闸/摆渡系统
   * 日志审计与运维监控平台

## 3.3 部署架构

### 3.3.1 逻辑部署

* 互联网前端：群众线索填报端，部署在互联网区；
* 数据摆渡区：通过单向光闸/安全交换平台进行数据同步；
* 检察内网业务区：部署检察端业务系统、AI 服务、数据库、对象存储、日志审计服务。

### 3.3.2 部署要求

* 前后端物理隔离；
* 后端仅允许内网访问；
* 敏感数据不落地互联网区；
* 音视频、附件、OCR 结果、AI 审查结论均在内网处理；
* 所有调用必须经过统一认证、授权与审计。

## 5. 各模块概要设计

## 5.1 系统首页：办案总览大屏

### 5.1.1 功能目标

为检察官提供办案入口、任务聚焦、风险预警、区域态势总览，提升每日办案调度效率。

### 5.1.2 页面组成

1. 顶部固定区
2. 核心指标看板区
3. 我的待办任务区
4. 今日线索动态区
5. 案发地点热力图区
6. 高风险涉稳线索预警区

### 5.1.3 核心实现细节

#### （1）顶部固定区

* 展示系统主标题、检察院名称、登录人信息、角色权限、公告入口、待办红点与退出按钮；
* 待办红点通过消息中心和任务中心聚合生成；
* 公告信息由系统管理后台统一发布。

#### （2）核心指标卡片

* 指标来源于统计服务实时汇总；
* 支持 T+0 刷新与定时缓存刷新；
* 指标计算需明确口径，例如：

  * 待研判线索：状态=待研判且未作废；
  * 待审查重点线索：前端勾选“需要支持起诉”且状态=待审查；
  * 办理中案件：案件状态 in（受理、调查中、文书审核中）；
  * 已办结案件：案件状态=已办结。

#### （3）待办任务清单

* 任务按“风险等级 > 超期程度 > 提交时间”排序；
* 支持“立即办理”“一键分流”；
* 待办任务来源：线索处理节点、案件办理节点、文书审核节点、督办节点。

#### （4）今日线索动态

* 通过滚动消息流实时展示；
* 自动叠加“重复诉求”“聚合线索”“高风险”标签；
* 支持点击跳转对应线索详情。

#### （5）高风险预警看板

* 风险等级由规则引擎 + AI 研判共同生成；
* 预警规则示例：

  * 涉及人数 ≥ 30；
  * 欠薪金额 ≥ 50 万；
  * 近 7 日重复投诉 ≥ 3 次；
  * 敏感时间节点群体性投诉；
* 支持“一键督办”生成督办任务并通知责任人。

### 5.1.4 关键非功能要求

* 首页首屏加载时间 ≤ 3 秒；
* 地图热力渲染响应时间 ≤ 2 秒；
* 指标数据允许分钟级缓存，但风险预警应支持近实时刷新。

## 5.2 线索全生命周期管理模块

### 5.2.1 功能目标

实现线索从接收、识别、聚合、分流、审查到办结、归档的闭环管理。

### 5.2.2 子功能分解

1. 线索接收与入库
2. 线索查询与筛选
3. 分类导航树
4. 线索详情展示
5. 智能聚合
6. 重复诉求识别
7. 线索分流指派
8. 流程跟踪与留痕

### 5.2.3 业务流程

1. 外部线索进入内网；
2. 系统完成结构化解析与 AI 预分析；
3. 进入待研判池；
4. 检察官研判后，执行受理、分流、补证、终结等操作；
5. 形成案件后进入办案流程；
6. 办结后归档并同步统计。

### 5.2.4 关键实现设计

#### （1）线索接收与标准化处理

* 接收来源：前端自主填报、12345、共享交换平台、移送单位；
* 入库前执行：

  * 字段校验（必填项、格式、时间合法性）；
  * 身份信息脱敏；
  * 地址标准化；
  * 诉求文本清洗；
  * 附件元数据抽取；
  * 生成唯一线索编号。

#### （2）筛选与高级检索

* 常规筛选：状态、风险等级、案发区域、时间；
* 关键字搜索：支持工地/企业/包工头/诉求关键字；
* 高级检索：支持布尔组合、金额区间、人数区间、来源组合、标签组合；
* 建议使用全文检索引擎建立倒排索引与向量索引，支持关键词检索 + 语义检索。

#### （3）分类导航树

* 分类树支持按来源、诉求类型、聚合维度、处理状态多维切换；
* 分类树与列表联动刷新；
* 支持节点计数、颜色标识与快捷筛选。

#### （4）线索详情页设计

线索详情建议分为以下页签：

* 基本信息
* 诉求内容
* 证据材料
* AI 预分析
* 分流记录
* 流程时间轴
* 操作日志

#### （5）诉求原文一键润色

* 由文书生成模型对口语化表达进行规范化改写；
* 保留原文与润色后版本双轨存储；
* 润色结果需支持“预览—确认—同步”；
* 同步目标可选：案件事实摘要、分析报告、文书草稿。

#### （6）智能聚合实现机制

聚合采用“规则 + 模型”的混合模式：

* 规则层：身份证号、手机号、统一社会信用代码、工地关键字硬匹配；
* 模型层：地址向量、项目名向量、主体名称向量、诉求事实向量相似度计算；
* 综合评分：

  * 地址相似度 35%
  * 项目名相似度 25%
  * 涉事主体相似度 20%
  * 包工头/联系人相似度 10%
  * 诉求事实相似度 10%
* 当综合评分 ≥ 阈值（默认 0.85）自动建议聚合；
* 低于阈值但高于预警值（如 0.70）进入人工待确认池。

#### （7）重复诉求识别机制

* 主键判重：身份证号 + 手机号 + 姓名；
* 辅助判重：诉求语义相似度、项目名、时间窗口、涉事主体；
* 同一事实多次提交时建立“主诉求 + 重复记录”关系；
* 支持检察官决定：合并处理 / 单独保留 / 不予重复受理。

#### （8）线索分流与协同

* 分流对象：检察官、部门、属地检察院、外部协同单位；
* 分流时需填写：接收方、分流依据、备注、办理时限；
* 分流后自动产生待办、消息通知、留痕记录；
* 对外部单位的移送建议采用标准交换接口或安全导出文书。

#### （9）流程时间轴

* 时间轴节点包括：提交、入库、AI 预分析、人工研判、分流、补证、受理、调查、文书审核、办结、归档；
* 每个节点记录：操作人、角色、时间、动作、意见、附件；
* 时间轴数据不可物理删除，仅允许追加和状态修订。

### 5.2.5 模块输入输出

* 输入：线索表单、共享交换数据、附件、人工操作指令；
* 输出：线索实体、聚合结果、重复识别结果、分流记录、流程记录、待办任务。

## 5.3 AI 辅助审查与办案模块

### 5.3.1 功能目标

通过规则引擎与大模型辅助，实现支持起诉条件审查、证据分析、初步报告生成与履职提示。

### 5.3.2 子功能分解

1. 支持起诉资格审查
2. 审查依据提示
3. 问题清单提示
4. 初步分析报告生成
5. 履职办案指引
6. 证据真实性与语义分析
7. 审查意见确认与驳回

### 5.3.3 审查机制设计

#### （1）审查模式

采用“双引擎模式”：

* 规则引擎：负责刚性法定条件校验；
* AI 分析引擎：负责事实归纳、争议提炼、风险识别、材料缺失提示。

#### （2）审查维度

1. 申请人主体资格
2. 诉求是否明确
3. 基本事实是否具备初步证据支撑
4. 管辖是否适格
5. 是否超过诉讼时效
6. 是否属于支持起诉范围
7. 是否存在群体性、涉稳性风险

#### （3）结论生成逻辑

* 满足全部刚性条件：建议受理；
* 存在可补正问题：建议补充材料后受理；
* 存在实质性不符合条件：建议不予受理；
* 所有结论必须附带“依据 + 理由 + 风险提示”。

### 5.3.4 初步分析报告结构

1. 案件基本情况
2. 争议焦点归纳
3. 法律适用分析
4. 证据情况分析
5. 办案重点与难点
6. 补证建议
7. 办案优先级建议
8. 风险提示

### 5.3.5 履职提示设计

履职指引按“取证、询问、协调、风险防控、文书制作”五类输出：

* 取证清单：缺失材料及调取建议；
* 询问提纲：针对申请人、企业、包工头分别给出问题模板；
* 协同建议：建议联动的人社、住建、工会等单位；
* 风险防控：群体性事件稳控建议；
* 文书要点：支持起诉意见书需重点论证内容。

### 5.3.6 证据审查设计

#### （1）书证审查

* 对合同、欠条、流水、考勤、工资表等进行 OCR；
* 自动抽取：主体、金额、日期、签章、页码、关联项目；
* 检测缺陷：签章缺失、金额不一致、内容模糊、时间矛盾、上下文缺页。

#### （2）音视频审查

* 通过 ASR 转写为文本；
* 自动提取关键片段、人物发言、时间点、核心语义；
* 生成“证据摘要 + 关键时间轴 + 风险提示”。

### 5.3.7 人机协同控制

* AI 输出均标注“仅供参考”；
* 检察官必须执行“确认审查意见”或“驳回审查意见”；
* 被驳回的 AI 结果保留版本记录，用于后续模型优化但不得替代人工决定。

## 5.4 法律文书智能生成与管理模块

### 5.4.1 功能目标

基于模板引擎、案件要素抽取与 AI 生成能力，实现文书草拟、审核审批、签章归档全流程管理。

### 5.4.2 子功能分解

1. 文书模板库
2. 文书草稿生成
3. 文书编辑器
4. 审核审批流
5. 签章打印
6. 归档管理
7. 版本管理

### 5.4.3 模板库设计

模板按办案节点分类：

* 受理前文书
* 调查取证文书
* 支持起诉核心文书
* 送达文书
* 结案归档文书

模板管理要求：

* 统一版式、统一页眉页脚、统一编号规则；
* 支持模板版本控制；
* 支持本地化条款与院级个性化模板扩展；
* 模板字段支持自动映射。

### 5.4.4 文书生成实现机制

* 结构化字段自动填充：案号、当事人、诉求、金额、项目等；
* 非结构化内容由 AI 生成初稿：事实概括、审查意见、法律依据、建议结论；
* 生成策略采用“模板骨架 + 要素填充 + 段落生成 + 规则校验”；
* 生成后自动执行格式校验、字段完整性校验、敏感表述校验。

### 5.4.5 审核审批流程

推荐采用可配置工作流：

* 承办检察官提交；
* 部门负责人审核；
* 分管副检察长审批；
* 对重大疑难涉众案件可增加“检察长审批/检委会讨论”节点；
* 退回时需填写退回意见，形成修订闭环。

### 5.4.6 版本与留痕设计

* 每次保存生成一个草稿版本；
* 每次提交审核锁定一个送审版本；
* 审批意见、修改痕迹、签章记录、打印记录全部留存；
* 支持版本对比查看。

### 5.4.7 文书输出与归档

* 支持导出 Word/PDF；
* 支持电子签章；
* 支持打印与归档；
* 支持与检察业务应用系统对接，减少重复录入和重复上传。

## 5.5 批量办案与类案管理模块

### 5.5.1 功能目标

针对同工地、同企业、同类型欠薪线索，提升批量办理效率，统一办案口径。

### 5.5.2 子功能分解

1. 类案自动聚合
2. 合集管理
3. 批量审查
4. 批量分流
5. 批量文书生成
6. 批量状态流转
7. 类案规则推送

### 5.5.3 聚合逻辑

* 以工作地点、涉事主体、诉求事实为核心维度；
* 支持按六级地址颗粒度自定义聚合；
* 自动生成“类案合集”实体；
* 合集中保留单案独立性与合集共性信息。

### 5.5.4 批量操作约束

* 仅对满足同类处理条件的线索开放批量操作；
* 批量审查必须保留逐案结果；
* 批量文书生成支持“统一模板 + 个案变量”；
* 对批量操作失败的个案需支持局部回滚与异常重试。

### 5.5.5 类案规则推送

* 关联本地案例库、裁判规则库、院内经验库；
* 根据合集标签推送相似案例与办理建议；
* 供检察官统一裁量尺度时参考。

## 5.6 数据统计与分析模块

### 5.6.1 功能目标

为案件研判、专项整治、源头治理、绩效评价提供多维数据支撑。

### 5.6.2 子功能分解

1. 综合统计报表
2. 区域分布分析
3. 趋势分析
4. 办案质效分析
5. 风险专题分析
6. 导出与报送

### 5.6.3 指标体系设计

#### （1）线索类指标

* 线索总量、日均新增量、来源分布、类型分布、重点线索占比、重复诉求占比。

#### （2）案件类指标

* 受理率、补证率、不予受理率、办结率、平均办结时长。

#### （3）文书类指标

* 文书生成量、审核通过率、平均审核时长、退回修改率。

#### （4）质效类指标

* 检察官人均办案量、采纳率、纠错率、超期率。

### 5.6.4 展现方式

* 卡片、柱状图、折线图、饼图、热力图、排行表；
* 支持按时间、区域、单位、检察官、工地、企业等维度钻取；
* 支持导出 Excel/PDF 报表。

## 5.7 系统设置与数据安全保障模块

### 5.7.1 功能目标

保障系统运行安全、数据安全、权限安全、审计合规与可运维性。

### 5.7.2 子功能分解

1. 用户与角色权限管理
2. 组织机构管理
3. 字典与参数配置
4. 流程配置
5. 模板管理
6. 接口管理
7. 日志审计
8. 安全策略管理

### 5.7.3 权限模型

建议采用 **RBAC + 数据权限 + 场景权限** 三层控制：

* RBAC：按角色控制菜单、按钮、接口；
* 数据权限：按院、部门、案件承办关系控制数据可见范围；
* 场景权限：对敏感证据、完整身份信息、文书审批操作进行二次校验。

### 5.7.4 数据安全设计

1. 敏感字段加密存储（SM4）；
2. 传输链路国密加密；
3. 密钥分级管理；
4. 敏感字段脱敏展示；
5. 敏感访问实名审计；
6. 附件独立加密存储；
7. 支持双因子查看或查看密码机制（可选）。

### 5.7.5 数据生命周期管理

* 在线数据：在办案件数据；
* 归档数据：已办结卷宗数据；
* 销毁数据：达保留期限后经审批执行不可恢复删除；
* 所有销毁动作需审批、留痕、可审计。

## 6. 关键业务流程设计

## 6.1 线索受理流程

外部提交 → 摆渡入内网 → 标准化解析 → AI 预分析 → 待研判 → 人工研判 → 受理/补证/分流/不予受理。

## 6.2 支持起诉审查流程

进入审查页面 → AI 审查 → 查看证据 → 生成初步报告 → 检察官确认/驳回 AI 意见 → 形成审查结论。

## 6.3 文书审批流程

草稿生成 → 承办人修改 → 提交审核 → 部门负责人审核 → 副检察长/检察长审批 → 生效签章 → 归档。

## 6.4 批量办案流程

类案聚合 → 进入合集 → 批量审查 → 批量生成文书 → 批量审核/流转 → 批量归档。

## 9. AI 能力框架设计

## 9.1 AI 能力组成

1. OCR 识别模型
2. ASR 音视频转写模型
3. 语义向量匹配模型
4. 审查推理规则引擎
5. 文书生成大模型
6. 诉求润色模型

## 9.2 AI 调用策略

* 规则优先，模型补充；
* 高风险结论必须人工确认；
* 模型结果需保留置信度；
* 低置信度场景只给提示，不给结论；
* 模型提示词、模板、规则支持后台配置。

## 9.3 模型安全要求

* 模型部署于检察内网；
* 不得将敏感案件数据发送至公网模型；
* 输出内容需经过敏感信息与法律表述校验；
* 重要结论需支持可解释性展示。

## 11. 风险与控制措施

| 风险点       | 风险描述            | 控制措施                |
| --------- | --------------- | ------------------- |
| 聚合误判      | 同类线索错误合并或遗漏     | 阈值分层 + 人工校准 + 可拆分回退 |
| AI 误判     | 审查意见不准确         | 规则兜底 + 人工确认 + 置信度提示 |
| 附件识别质量不稳定 | 图片模糊、录音杂音导致识别偏差 | 质量检测 + 人工复核入口       |
| 数据安全风险    | 敏感信息泄露          | 国密加密 + 权限控制 + 日志审计  |
| 审批流复杂     | 多层审批节点配置混乱      | 流程模板化 + 管理员配置校验     |
| 批量处理误操作   | 批量流转影响大         | 二次确认 + 局部回滚 + 操作授权  |
