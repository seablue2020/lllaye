# 欠薪支持起诉智能办案平台（检察端）

## 技术报告

---

## 一、项目概述

### 1.1 项目背景

欠薪问题关乎农民工群体的切身利益与社会和谐稳定。检察机关依法开展支持起诉工作，是维护弱势群体合法权益的重要职能。然而，传统办案模式面临线索分散、证据审查耗时、类案处理效率低、文书撰写负担重等痛点。

本项目构建了一套面向检察端的**欠薪支持起诉智能办案平台**，以 Vue 3 + NestJS + PostgreSQL 为技术底座，深度融合大语言模型（DeepSeek API），实现从线索采集、AI智能审查、类案聚合、批量办理到文书生成的全流程数字化、智能化支撑。

### 1.2 系统定位

本平台服务于省/市/区三级人民检察院，为承办检察官、部门负责人、分管副检察长等角色提供统一的案件办理工作台，覆盖线索管理、AI辅助审查、类案聚合、文书审批、统计分析等核心业务场景。

## 四、核心技术亮点

### 4.1 AI 深度赋能检察业务（核心亮点）

本平台将 DeepSeek 大模型深度嵌入办案流程，是区别于传统办案系统的核心技术特色。

#### 4.1.1 AI 预分析（线索录入时触发）

线索提交后，系统自动调用 AI 对以下维度进行预判：

- **风险等级评估**：根据人数（≥30人=高风险）、诉求类型等自动定级
- **风险原因识别**：群体性事件预警、涉稳风险提示
- **处置建议**：自动分配承办检察官，创建待办任务和消息通知

#### 4.1.2 AI 多维度案件审查

对案件进行 6 个维度的专业化审查：

| 审查维度 | 说明 |
|----------|------|
| 申请人主体资格 | 判断是否为农民工/困难群体 |
| 诉求明确性 | 诉求内容是否清晰、具体 |
| 基本事实证据 | 是否有初步证据证明欠薪事实 |
| 管辖合规性 | 案件是否在本院管辖范围内 |
| 诉讼时效 | 是否超过法定诉讼时效 |
| 风险等级评估 | 人数规模、金额、群体性风险综合评估 |

每个维度返回 `pass / warning / fail` 三态结论、置信度（0~1）、法律建议，并附带缺失证据清单和引用法条。审查结论分为"受理 / 需补证 / 不予受理"三种。

#### 4.1.3 AI 文书智能生成

支持根据案件信息自动生成：

- **支持起诉意见书**（草稿）
- **初步分析报告**（含争议焦点、法律适用、证据分析、补证建议、风险提示）

文书生成后进入审批流，AI 生成内容可由检察官修改确认，保证法律文书的严谨性与权威性。

#### 4.1.4 AI 诉求智能润色

将群众口语化欠薪表述（如"包工头欠我钱"、"一直拖不给"）自动转化为规范法律用语，提取关键要素（金额、时间、主体），提升线索录入效率和信息规范性。

#### 4.1.5 AI 证据辅助审查

证据材料（含 OCR 结果、音视频转写）可提交 AI 审查，返回证据有效性评估和关键片段标注。

> **技术实现**：AI 服务层封装为独立的 `AiService`，通过环境变量配置 API Key 与 Base URL，支持切换不同模型。当 API Key 未配置时自动降级为本地 Mock 实现，确保开发/演示环境可用。温度参数（temperature）设置为 0.1~0.3，兼顾创造性与准确性。

### 4.2 敏感数据加密与脱敏

敏感个人信息（身份证号、手机号码）采用 **AES-CBC** 加密存储，同时生成脱敏副本（`****` 掩码）用于前端展示，防止隐私泄露：

```typescript
// 加密存储
applicantIdNo: this.encryption.encrypt(dto.applicantIdNo)  // AES-CBC Base64
applicantIdNoMasked: this.encryption.maskIdNo(dto.applicantIdNo)  // "4201****1234"

// 查询返回（展示脱敏数据）
applicantIdNoMasked: true  // Prisma select 过滤
```

密码使用 **bcrypt**（cost factor = 10）单向哈希存储，不可逆。

### 4.3 Redis 分布式编号生成

线索编号（`CX-YYYYMMDD-XXXX`）和案件编号（`AJ-YYYYMMDD-XXXX`）通过 Redis `INCR` 原子操作生成，保证高并发下编号唯一且连续，避免数据库序列锁竞争：

```typescript
private async generateClueNo(): Promise<string> {
  const today = dayjs().format('YYYYMMDD');
  const key = `clue:no:${today}`;
  const count = await this.redis.incr(key);  // 原子递增
  await this.redis.expire(key, 86400);      // 当日过期，避免无限增长
  return `CX-${today}-${String(count).padStart(4, '0')}`;
}
```

### 4.4 类案智能聚合与批量处理

系统支持按**同一项目、同一主体、同一包工头、同一区域**四个维度对类案线索进行智能聚合：

- 自动发现符合条件的线索组（≥2 条）
- 计算聚合汇总数据（总金额、总人数、高风险线索数）
- 批量受理/驳回/分流操作
- 合集拆分能力（移除误聚合的线索）

相似度评分机制（`similarityScore`）标记代表性线索，支撑差异化处理策略。

---

### 4.5 多层级文书审批流

文书审批采用多级流水机制：

1. **承办检察官** → 发起审批
2. **部门负责人**（一级审批）→ 审批/退回
3. **分管副检察长**（二级审批）→ 审批/退回
4. 全部通过后进入**签章归档**环节

每个审批节点独立记录审批意见和电子签章 URL，支持文书版本管理（每次修改生成新版本快照）。

---

### 4.6 全链路操作审计

通过 NestJS 拦截器（AOP 思想）对所有数据变更操作（POST/PUT/DELETE）自动记录审计日志：

- 操作人、时间、IP、User-Agent
- 操作模块、业务ID、变更详情（JSON）
- 分类索引支持按用户/模块/时间快速查询

---

### 4.7 重复投诉智能检测

新线索提交时，自动检索与以下字段存在交集的历史线索：

- 同一申请人姓名
- 同一涉事主体名称
- 同一项目/工地名称

将疑似重复线索展示给承办人，支持合并或保留处理，节省重复审查资源。

---

### 4.8 区域热力图与统计分析

- **区域分布热力图**：基于 PostGIS 标准化地址，按区县聚合线索分布，ECharts 地图可视化
- **趋势分析**：支持日/周/月维度的线索、案件、金额趋势折线图
- **办案质效分析**：平均办理时长、各阶段流转效率统计
- **综合统计报表**：按机构、时间范围筛选的汇总数据

---

### 4.9 RBAC 权限体系

基于角色的访问控制（Role-Based Access Control），5 种内置角色：

| 角色 | 权限码 |
|------|--------|
| 系统管理员 | `*`（全部权限） |
| 承办检察官 | `clue:*`, `case:*`, `review:*`, `document:*` |
| 部门负责人 | `review:*`（含审批）, `statistics:*` |
| 分管副检察长 | `document:approve`, `statistics:*` |
| 审计员 | `audit:*`, `statistics:*` |

通过 NestJS 守卫（`RolesGuard`）+ 装饰器（`@Roles('admin')`）在路由层实施权限控制。
